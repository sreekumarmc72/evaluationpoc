# Downloadable evaluation reports

Completed evaluations offer **Download PDF** in the shared results view used by the student page, original POC and faculty submission history. GET `/api/evaluations/:id/report.pdf` produces an A4 PDF from the currently saved result. It does not call OpenAI, persist another result, migrate exams, or change marks. Existing saved evaluations are supported, including records without criterion rubrics. Expired original-POC runs cannot be recovered by report generation.

The layout opens with a branded score dashboard, section-score table and question overview (maximum, award, assessment status and whether counted). Detailed assessments use question header bands, rubric tables with separate marks and evidence columns, and colored feedback headings for correct points, deductions and review. Tables use alternating row shading, repeat column headings on continuation pages and split oversized cells without discarding text. Regular and bold Noto Sans fonts are bundled. Summaries deliberately repeat marks; they do not add a second contribution to totals. The detailed content remains complete, so large exams can produce long reports.

Reports contain the exam title, student name (manual entry takes precedence), submission identifier, evaluation date in IST, displayed and calculated totals where different, section totals and counted questions, question awards, criterion maxima/awards, expected evidence and answer-key basis, student evidence, deductions, correct/missing points and academic review recommendations. Provisional awards and optional exclusions remain visible. Faculty adjustments are separate from the original AI criterion awards. Detailed question-paper text is not reprinted; identifiers/labels connect the report to the paper.

The report is an allowlisted projection, not an export of the entire run or a printout of the screen. It excludes raw transcription, page images, name-reading evidence, processing notes/warnings, answer mapping, source-entry identifiers, API/model metadata, timings, token counts and recovery diagnostics. Sentence-level filtering additionally removes processing commentary embedded in grading feedback. There is no AI rewrite. If the only review explanation was technical, a generic review recommendation remains; the report never promotes a provisional award to final or fabricates a deduction explanation. Original detailed diagnostics remain in the application.

The download uses the existing access middleware: a saved submission requires its student's original browser cookie or a faculty session. Another student's cookie cannot download it. Incomplete/failed runs return 409. Downloads use attachment disposition and the application's no-store headers. Old PDFs already downloaded are snapshots; downloading again reflects saved name/mark changes.

Rendering uses existing `pdf-lib` plus `@pdf-lib/fontkit` and a bundled OFL-licensed Noto Sans font. Docker already copies API sources, including the font and license; no extra Render environment variables or services are needed. Rupee signs and supported mathematical symbols are preserved. Unicode minus is rendered as an equivalent hyphen-minus; unsupported glyphs use explicit code-point notation rather than silently disappearing. Equations are reported in their saved text form, not recomputed or typeset as new mathematical answers.

Verification: projection tests cover legacy results, provisional/adjusted awards, rounding, optional exclusions and technical filtering; PDF tests cover Unicode and multipage output; route tests cover faculty/student/cross-student access; shared UI tests cover download availability. A private PDF generated from the existing 36-question Financial Reporting result was rendered for visual checks. No paid model evaluation was run for this feature.
